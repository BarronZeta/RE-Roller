RE: Roller by Vash 0.9.3 - Performance diagnostics

WHAT CHANGED
Opening /rr, using Refresh and processing idle build changes now spread the
read-only build scan across frames. Successful display metadata is cached for
the current session. Unchanged row/icon/style work and duplicate idle refreshes
are reduced. The interface layout, artwork, fonts and Quick animation remain.

WHAT DID NOT CHANGE
Every reroll request still needs a complete fresh build/spec/lock check. Every
result still needs the native result signal, one actual replacement and exactly
one matching scroll. Full request/result reads remain synchronous in this release.
No partial read can authorize a request. Combat, stale-spec, stop, timeout and
protected-action guards remain. Settings, locks and history use the same schema.

TEST WITHOUT SPENDING SCROLLS FIRST
1. Replace only the GrimfallReroll addon folder, then reload/restart the client.
2. Open /rr and wait for "Reading build across frames..." to finish.
3. Run /rr perf reset. Click Refresh once, wait until it finishes, then /rr perf.
4. Send the complete report and note whether Refresh feels smoother. Version
   should read 0.9.3. No reroll or scroll use is needed for this first test.
5. If you already intend to reroll, reset the report again while idle, perform
   those intended rolls, then send /rr perf and note when any hitch occurs:
   window opening, Refresh, clicking reroll, native animation, or result display.

FALLBACKS
/rr smooth off     Synchronous display refresh for this session.
/rr smooth on      Frame-spread display refresh for this session (default).
/rr refresh sync   One manual full refresh, only with no outstanding reroll.
/rr stop           Stop the queue/cancel an active display refresh as before.
The smooth setting is intentionally not saved. Reload returns to the default.
If a read-only scan times out, close the window, use /rr smooth off, then reopen
or /rr refresh sync while idle. A timeout does not send a reroll or retry one.

HOW TO READ THE REPORT
"snapshot work" is active CPU/native-call work, excluding waiting between frames.
"read-only refresh slice" is work in one scan frame, not the whole game frame.
"read-only refresh wall time" includes the time waiting between those frames.
Stage timings include their API timings; do not add them together.
Slowest native tree read identifies one costly tab lookup. A native game call
cannot be paused by this addon, so it can exceed the nominal 4 ms slice target.
Warm metadata can reduce repeated spell lookups, but build events invalidate it.
Frame gaps include the game and other addons; they do not prove a single cause.

VALIDATION AND LIMITS
139 mocked Lua 5.1 regressions and six module compilation checks passed.
Golden old/new build rows, keys, ranks, IDs, names and icons match. A controlled
API-cost simulation showed smaller read-only slices and fewer warm lookups;
cold reads were unchanged. These are injected costs, not measured game FPS.
This update has not been verified in the affected tester's game client.
Full synchronous request/result checks can still hitch and need fresh timings
before considering a more invasive validation redesign.

Install only GrimfallReroll. This package does not include or modify Postal,
Auctionator, Build Suite Manager, game settings or any SavedVariables files.
Published as a regular release. Release status does not imply measured FPS gains.
