# RE: Roller by Vash 0.9.7

Batch build reads, Titan/Clean appearance selection, and compact history.
This is a regular release, including the locally tested 0.9.5 and 0.9.6 changes
since the previous public 0.9.4 release.

## Download and update

Download **RE-Roller-0.9.7.zip** from this release's Assets. It contains only the
`GrimfallReroll` addon folder and its required assets and license notices.
GitHub's automatic Source code archives are not the ready-to-install download.

With WoW closed, back up your existing addon folder and RE:Roller saved-variable
files before replacing the addon folder. **History now retains the newest 20
ability rolls and 20 talent rolls per character.** Older records are pruned at
load; keep a local backup if you want to retain them. Do not delete your WTF
folder, and do not upload account files to GitHub.

## What's new

- **Batch reads by default:** a normal six-roll queue reads the complete build
  once at startup and once after the final result finishes native presentation.
  Lists and history do not refresh between rolls.
- **Sequential acknowledgements:** each roll still waits for its result, exactly
  one matching scroll consumed, and native presentation completion. Only one
  request is outstanding; replacement entries are never added to the queue.
- **Pacing and diagnostics:** a 100 ms minimum gap, 50 ms active readiness polling,
  next-frame event wakeups, and expanded `/rr perf` and `/rr pace` reports.
- **Titan or Clean:** switch instantly with the Skin button, `/rr skin titan`,
  or `/rr skin clean`. The preference is saved without changing the build.
- **Compact layout:** more space below the header; a controls-only footer with
  Skin, Quick Animation, Pause, Stop and Clear; smaller history icons and rows.
- **Independent history panels:** show or hide either side with its History
  checkbox. Each history retains its own newest 20 rolls.
- **Replacement-lock fix:** newly verified replacements no longer inherit a
  dormant lock when they were absent from the starting build. Existing learned
  protections and other specs are preserved. Already-hidden entries still need
  an explicit one-time unlock.

## Batch behavior and limits

The full comparison for unrelated build changes now happens at the end, not
between requests. Avoid manual ability/talent changes, spec switches, and other
reroll tools during a batch. Combat, death, spec changes, blocked actions,
unexpected scroll changes, and ambiguous results stop further requests.

Pause/Stop still observe an outstanding request. Confirmed history and chat
results are committed only after final build verification. A stopped partial
batch also gets verified. If final client data is delayed, bounded additional
final reads may be needed; no reroll is automatically resent.

Use **`/rr batch off`** while idle for the previous complete per-roll verification,
or **`/rr batch on`** to restore batch mode. Initial/final native reads may still
hitch; fewer reads do not make the underlying game API faster.

## Validation and reporting

- 243 offline behavior/layout tests pass in Lua 5.1 and a separate MoonSharp runner.
- Six-roll ability and talent tests verify six requests and exactly two full reads.
- Seven Lua modules compile; ten offline skin/history layout checks pass.
- The 39-file addon package matches the locally installed 0.9.7 files.
- Supplied in-game screenshots confirm the displayed interface; they are not
  a live speed/FPS benchmark. No measured in-game performance gain is claimed.

For the next queue you already intend to run, wait for the opening display read,
use `/rr perf reset`, complete the queue, then include `/rr perf` and `/rr pace`
with any issue report. State whether a hitch occurred at startup, between rolls,
or at the end. Do not spend scrolls solely to benchmark.

**Compatibility:** Grimfall's custom WoW 3.3.5a client only. This release does not
modify BSM, Postal, Auctionator, or other addons.
